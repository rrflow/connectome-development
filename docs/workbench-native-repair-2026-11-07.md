This records work in draft [Connectome PR #40](https://github.com/rrflow/connectome-development/pull/40). The candidate reconciles user revision `5542691e28605a4a14841b1215935468d06fc0f3` with Connectome main `ae73c3c31cd3838a0131ffe259a5f7e211abdd38`. The PR remains draft until its final diff, dependency, candidate CI, merge-group checks and rendered desktop journey are reviewed. RRFlow's separate engram repair is [PR #290](https://github.com/rrflow/rrflow-development/pull/290).

The Reasoning workbench calls the pinned engine's observe-flight operation. The desktop displays the engine's returned flight events and creation-order cursor pages; it lets an operator create workbenches, save local notes, and explicitly capture engine diagnostics separately from engine audit. Existing notes remain readable. The operation stores the submitted prompt and does not run LFG, SWAG or a language model. Native graph, schema, vector and storage lenses continue to use the existing engine-backed clients. Graph layout and clusters are presentation, not newly persisted relationships.

On Windows, `pnpm check` and `pnpm build` passed. The four browser smoke tests passed with a temporary Playwright configuration on port 4189 and server reuse disabled; they exercise the disconnected workbench and local notes, not a connected desktop. The first smoke failed because the new tab changed the Reasoning area's default destination; the final tab ordering preserves Tasks as the default. A later attempt reused an unrelated server on the default port and was invalid; a no-reuse attempt correctly refused the occupied port. Native `cargo fmt --manifest-path src-tauri/Cargo.toml --all -- --check`, `cargo clippy --offline --locked --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings`, and `cargo test --offline --locked --manifest-path src-tauri/Cargo.toml --all-targets` passed; the ordinary native suite reported 54 passed and 24 ignored.

For real-process checks, the engine was built offline from a clean checkout of the exact SDK pin `f45305394dbe391786c7d618645a5fc0b1b2bbee`. Its SHA-256 was `93e4fe2d2efbbc8f04d96cd50d37412f0fc285917c2d13a27d5d8eb2326eab10`. It installs a temporary project and verifies a synthetic fixture's documents, relationships, queries, vectors and physical storage counters through the authenticated native client.

The added `rrd::client::process::observe_flight_is_read_back_after_reconnecting` test initially failed because the desktop requested protocol maximum graph depth 32 while the installed engine's configured limit was 4. The desktop now obtains the running engine's validated recall limits before launch. The test then passed using nine observe flights, two cursor pages and readback after reconnect. If configuration changes between the capability read and admission, the engine may reject the request and the UI reports that rejection. This test alone does not prove desktop rendering, provider quality, real-project indexing, other operating systems, C-07 qualification or release readiness.
