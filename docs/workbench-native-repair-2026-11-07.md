The Reasoning workbench calls the pinned engine's observe-flight operation. The desktop displays the engine's returned flight events and creation-order cursor pages; it lets an operator create workbenches, save local notes, and explicitly capture engine diagnostics separately from engine audit. Existing notes remain readable. The operation stores the submitted prompt and does not run LFG, SWAG or a language model. Native graph, schema, vector and storage lenses continue to use the existing engine-backed clients. Graph layout and clusters are presentation, not newly persisted relationships.

On Windows, `pnpm check` and `pnpm build` passed. The four browser smoke tests passed with a temporary Playwright configuration on port 4189 and server reuse disabled; they exercise the disconnected workbench and local notes, not a connected desktop. The first smoke failed because the new tab changed the Reasoning area's default destination; the final tab ordering preserves Tasks as the default. A later attempt reused an unrelated server on the default port and was invalid; a no-reuse attempt correctly refused the occupied port. Native `cargo fmt --manifest-path src-tauri/Cargo.toml --all -- --check`, `cargo clippy --offline --locked --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings`, and `cargo test --offline --locked --manifest-path src-tauri/Cargo.toml --all-targets` passed; the ordinary native suite reported 54 passed and 24 ignored.

The desktop now obtains the running engine's validated recall limits before launch. The test then passed using nine observe flights, two cursor pages and readback after reconnect. If configuration changes between the capability read and admission, the engine may reject the request and the UI reports that rejection.
