# Inherited capability parity

**Status:** active record, read on 2026-11-18 against `main` at `827abb35` and the engine at `cc5ebe0fd`

What the inherited views can do, capability by capability, and whether the native RRD client and the RRFlow engine can do it today. Nothing inherited is removed until its row here reads **native**.

## How this was made

Ten readers each took one area of the inherited client, read its files in full, and listed every user-facing capability with the inherited calls it depends on. Each was mapped to the native RRD client (`src/rrflow`, `src-tauri/src/rrd`) and to the engine's public operations and rrflowQL, and the cited native code was opened. A second reader then tried to refute every claim that a capability is covered; a refuted claim takes the corrected status below. A last reader looked for what all ten missed.

Limits: 85 inherited files were read by no area and 26 capabilities were missed (both listed at the end), so the totals are a floor. Statuses come from reading code, not from running it. The full data, with the inherited paths per capability, is in [`inherited-capability-parity.json`](inherited-capability-parity.json).

## Query studio

### Native (8)

- **Query editor with rrflowQL highlighting.** Type a query in a CodeMirror editor with rrflowQL token highlighting (keywords, source family, kind, field, parameter, string, number, bool, null, invalid tokens).
  - Native: src/features/runtime/components/query-editor.tsx QueryEditor uses the same rrflowql() from ~/editor/rrflowql; used by src/features/runtime/query-lab/query-lab.tsx QueryLabView.
  - Gap: None for highlighting. The inherited pane additionally passes scrollPastEnd(), lineNumbers and autoCollapseDepth to CodeEditor; the native editor passes none of these (see 'Editor appearance settings').
- **Select the statement under the cursor (Mod-E).** Ctrl/Cmd+E selects the query the cursor is in.
  - Native: src/features/runtime/components/query-editor.tsx binds Mod-e to getQueryRange (src/editor/rrflowql/codemirror/range.ts) and selects it; the lab's hint names the key. Smoke: tests/smoke/connectome.spec.ts 'the query lab sends typed variables and runs only what is selected'.
  - Gap: None. The engine takes one statement per request, so the statement under the cursor is the query; if multi-statement text is ever accepted, getQueryRange is the one place to split it.
- **Infer variables from query.** One click scans the query for $parameters, merges them into the variables object keeping existing values, opens the pane; reserved names are skipped.
  - Native: query-lab.tsx 'Infer variables' calls inferParameters (src/rrflow/query-parameters.ts), which reads the query's $names with classify(), adds each missing one as null, keeps every value already typed, and opens the pane. It refuses to touch text it cannot read. Tests: scripts/test-query-parameters.mjs; the smoke test.
  - Gap: None. rrflowQL has no reserved parameter names, so none are skipped.
- **Variable name autocompletion.** Typing $ offers the variables defined in the pane.
  - Native: src/editor/rrflowql/codemirror/complete.ts rrflowqlParameterCompletion, loaded by query-editor.tsx with the names that currently have a value in the variables pane.
  - Gap: None.
- **Pre-run lexical validation (lint) and its setting.** While typing (250 ms) the editor underlines what the tokenizer would refuse (unterminated string, bad escape, u64 overflow, unsupported character) with the engine's wording; the Run button is highlighted only when valid; 'Query validation' preference turns it off.
  - Native: query-editor.tsx loads rrflowqlLinting (src/editor/rrflowql/codemirror/lint.ts): what the engine's tokenizer would refuse is underlined with the engine's wording after 250 ms; query-lab.tsx turns Run red with that reason in its title. The behavior.queryErrorChecker setting turns it off. Smoke: the unterminated-string step of the query lab test.
  - Gap: None.
- **Engine error display.** A failed statement shows its error message in red monospace, selectable, sized by editor scale; a thrown error becomes a 'Failed to execute' notification.
  - Native: query-lab.tsx Alert 'The engine refused this query' with queryRefusal(error).reason; query-editor.tsx showRefusal marks the exact token (editor/rrflowql/codemirror/diagnostics.ts, engine/refusal.ts); src-tauri/src/rrd/error.rs:33 PARSE_REFUSAL supplies the UTF-16 offset.
  - Gap: None blocking. Note the offset is recovered by string-matching the engine's debug text at the pinned revision; a structured parse-error field in the engine contract would be sturdier.
- **Editor appearance settings.** 'Query editor line numbers' preference; editor scale applies to error text size; scroll past end.
  - Native: query-editor.tsx passes appearance.queryLineNumbers to CodeEditor, which already sizes text from appearance.editorScale and applies appearance.autoCollapseDepth.
  - Gap: None for the two settings. scrollPastEnd is not applied: a query is one short statement.
- **Sample / starter queries.** The sandbox connection seeds tabs with sample queries (basics, graph, vector); an empty result pane says 'Execute a RRFlowQL query to view the results here'.
  - Native: query-lab.tsx starters(): buttons built from the engine's real schema (record kind, EXPLAIN ANALYZE variant, relation kind) that fill the editor and run; explains when the schema lists no kinds or cannot be read.
  - Gap: None for this capability. The sandbox itself is another area.

### Engine cannot do it (3)

- **Multi-statement execution with per-statement results.** Put several statements in one editor, run them together, get one response per statement; 'Query N' picker lists each with row count and duration; result pane title 'Result #N'; picker resets to 1 when the response count changes.
  - Native: Engine: one statement per request (reference section 8; parser rejects trailing tokens); client.rs execute_query sends a single ExecuteQuery; QueryView has one columns/rows. No native UI.
  - Gap: Engine: no statement separator and no batch operation on query-execute. UI: either (a) the native studio splits the editor on a UI-level separator and issues N query-execute calls, showing a per-run result list with row count and client-measured time, or (b) the engine adds a batch read operation. Neither exists. Decide which before removing; (a) needs no engine change.
- **Writing data and schema from the query editor.** The inherited studio is a general console: CREATE, INSERT, UPDATE, UPSERT, DELETE, RELATE, DEFINE/REMOVE, LET, transactions run from the same editor as reads.
  - Native: Engine: rrflowQL has no data-modification or schema statements (reference section 9); writes are typed mutations through transaction-begin/preview/commit. Native client has previewChange/commitChange/discardChange (session.ts; src-tauri/src/rrd/client/transaction.rs) but no UI calls them. The rrflowQL `BEGIN; MUTATE $binding; COMMIT;` program is implemented in the engine (ExecuteQueryTransaction, crates/transport/rrd-contract/src/query.rs:157) with no catalogue operation.
  - Gap: Engine: either catalogue the transaction program as an operation or accept that writes are not query text. UI: a native change composer (typed mutations for record, relation, schema, vector, geo, series, retire) with preview of the prospective state and commit, reachable from the studio; this is safer than the inherited console (preview + digest echo) but does not exist. The native lab states 'Queries here only read'. Until one of these lands, removing the inherited studio removes the user's only write console.
- **Query language expressiveness available to the user.** In the inherited studio a user can sort, group, aggregate, call functions, use OR/NOT/IN, subqueries, graph arrows, multiple joins, comments, computed projections and aliases.
  - Native: Engine grammar: [SELECT] FROM <source> [JOIN ... ON a = b] AT VALID .. KNOWN .. [WHERE f op v {AND ...}] [PROJECT] [LIMIT] [EXPLAIN]; no ORDER BY, GROUP BY, aggregates, functions, OR/NOT/IN, subqueries, comments, aliases (reference sections 8-9; keyword set mirrored in src/editor/rrflowql/engine/classify.ts KEYWORDS).
  - Gap: Engine: these are language features the engine lacks, not UI work. What rrflowQL adds instead: mandatory bitemporal AT VALID/KNOWN, traversal source with depth, BM25 MATCH, EXPLAIN CONTRACT/ANALYZE with candidate paths. UI mitigation available now: client-side sort/filter in the result table and count/aggregate query indexes. Needs an owner decision on which constructs (at least ORDER BY, OR/IN, count) are required before removal.
