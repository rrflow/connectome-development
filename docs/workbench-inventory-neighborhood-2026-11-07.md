# Checkpoint-bound project inventory view

**Status:** Connectome PR #44 candidate. This is a narrow historical source-containment view, not complete project indexing, Parse, a current-source check, a general graph API, or alpha acceptance. RRFlow's objective, roadmap and POA&M remain authoritative.

## Scope and behavior

The workbench reads a bounded attunement job page, finds an Inventory checkpoint in the newest returned job with one, reads the checkpoint's snapshot digest, valid time and runtime cursor, and finds its root through the engine's `source-tree-contains` adjacency. It then reads one outgoing neighborhood and exact record labels at that same checkpoint stamp using authenticated RRFlowQL operations. It verifies the returned cursor, typed endpoints, identities and bounds. Failed or unauthorized reads do not produce a partial graph. Job pages not read and a limit hit or engine truncation are explicitly disclosed. Paths and relationships are returned by RRFlow, while graph positions are presentation only. The keyboard list offers the same navigation. A user can choose 20, 40 or 80 outgoing relationships; label reads run in batches of at most four.

The all-model diagnostic remains available on explicit request, but opening the workbench no longer automatically starts it through the page-level overview query. The diagnostic can exceed the configured response limit on large projects. The overview and the dedicated records and vectors lenses retain their existing diagnostic behavior. Physical-storage reads remain independent observations, not atomic with the checkpoint view. Session, checkpoint and selected-node identities scope the UI cache. The bounded first job page is not a complete job history; if it contains no checkpoint, the UI says none was found in that page. Discovery retries only engine-classified transient errors, at most three times; sustained conflicts remain visible.

## Remaining work and stop conditions

General bounded graph pagination, current source-generation identity and all consumer consistency remain engine work. Real-project Parse is unavailable in the tested engine, and a known interrupted-refresh test detects mixed generations. Further acceptance needs authorized mutation and replay/restart tests, session switching and native desktop checks, and protected candidate CI. A failure to bind the query to the returned checkpoint, an incomplete root, denied read, malformed identity or budget violation stops this view rather than inventing data or raising a response limit.
