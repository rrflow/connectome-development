## Change

The existing native task command calls the catalogue-derived `TaskBudgetResume`
operation once, using the displayed budget digest. Contract validation and the
engine own admission. The renderer exposes **Resume task budget** after readback
for inactive, known-completed cancelled/failed work. A pending resume blocks other
budget controls and clears prior request preparations. Lost replies require
readback; no automatic retry or model dispatch is introduced. Recovery without
a saved attempt also reconciles the budget's active/unknown state.

The budget projection includes original start and deadline as decimal strings;
the UI displays the deadline and explains retained effort. New work still needs
explicit input review and a separate request. The engine can deny expired,
exhausted, stale or changed-authority requests even when the control is offered.
No renderer credential, provider rank, hardcoded model, effect permission or
second lifecycle store is added.

Changed owners are `src-tauri/src/rrd/client/tasks.rs`, its installed process test,
`src/rrflow/tasks.ts`, `RuntimeConnection/tasks.tsx`, SDK manifests/lockfiles and
the real-process value fixture, plus this journal and workbench guidance.
The fixture must be regenerated by its existing writer against the exact pinned
engine, not relabelled. No implementation is removed or relocated.
